# Product

Golden product SSOT: the distilled, current truth of *shipped* ts-rogue behavior.
Upsert facts here (delete what shipped past); keep provenance and dates current.
`pnpm docs:lint` reports drift.

- ts-rogue is a replayable terminal dungeon crawler whose loop runs village, overworld, dungeon, battle, loot, and back to village. <source: PROJECT_PLAN.md and src/engine/world, 2026-07-23>
- The runtime is TypeScript on Node.js 24+ with Ink for the terminal UI, rot.js for procedural generation, seeded randomness, and a central serializable reducer store. <source: package.json and src/engine/state/store.ts, 2026-07-23>
- Engine modules must never import UI modules; the boundary is enforced by a biome rule. <source: biome.json and src/engine/README.md, 2026-07-23>
- Play is party-based: a multi-member party fights in battle, not a single hero. <source: src/engine/state/types.ts and src/engine/combat/resolution.ts, 2026-07-23>
- Characters have classes (warrior, rogue, wizard) that carry distinct skills and stats. <source: src/data/classes.ts and src/engine/combat/skills.ts, 2026-07-23>
- Loot is generated from item bases, affixes, and monster-implicit pools rather than hand-authored drops. <source: src/engine/loot and src/data/itemBases.ts, 2026-07-23>
- The first-person dungeon view renders perspective-projected wall faces and interactables as Braille wireframes. <source: src/ui/screens/dungeon/render.ts, 2026-07-23>
- The terminal UI ships a visual identity: a shared theme-token palette and an image tileset overlay. <source: src/ui/README.md and src/ui/tiles, 2026-07-23>
- Game state persists to a serializable save so runs resume across sessions. <source: src/persistence/save.ts, 2026-07-23>
- Linear owns issue status and priority; durable product truth lives in the repository. <source: CONTRIBUTING.md, 2026-07-23>
- The overworld/village support fast travel: evac exits any dungeon (outside battle) to the overworld on the entrance tile with dungeon progress untouched, and zoom teleports between landmarks (village, dungeon entrances) already visited this run; neither triggers an encounter or resets the overworld danger meter. <source: src/engine/world/waypoints.ts and src/engine/state/store.ts, 2026-07-25>
- A dedicated Inventory screen (opened anywhere outside battle) is the canonical place to browse gear/consumables/currency/quest sections, sort backpack gear by rarity/ilvl/slot/value, inspect an item's full affix lines, compare/equip/unequip gear per party member, and drink a heal item on a chosen party member in the field (village/overworld/dungeon); the village Store's backpack mode is sell-only, and the battle item command is unchanged. <source: src/ui/screens/inventory, src/engine/loot/consumables.ts, and src/ui/screens/village/StoreView.tsx, 2026-07-25>
- The village Stash gives unlimited storage for generated gear, separate from the field backpack's tunable cap (`FIELD_BACKPACK_CAP`, 20 slots); consumables, currency, and quest items never count against the cap. A full backpack forces a swap-or-dismantle triage prompt on the next gear drop instead of silently losing it. <source: src/engine/loot/inventory.ts, src/engine/loot/pickup.ts, and src/ui/screens/village/StashView.tsx, 2026-07-26>
- The Inventory screen's fifth section, Loot Filter, lets the player configure auto-dismantle rules live: a minimum rarity floor per dungeon tier, a minimum ilvl-vs-party-level offset, and an affix-stat keep-list; edits apply immediately and the rules persist in the save. A field drop is auto-dismantled into gold on pickup only when every configured rule fails (safety-net semantics: any one passing rule keeps the item). <source: src/engine/loot/lootFilter.ts, src/engine/loot/pickup.ts, and src/ui/screens/inventory/interaction.ts, 2026-07-26>
- The village is a multi-tile landmark: it occupies a 2x2 footprint derived from its anchor cell (`map.village`) plus a fixed size lookup, not stored per-cell. Both renderers draw it as one coherent structure - the Ink TUI with four distinct ASCII glyphs, the PixiJS renderer with one contiguous sprite tiled from per-cell texture sub-regions - and it stays enterable and non-overlapping with other terrain/landmarks from any of its four cells. <source: src/engine/world/landmarks.ts, src/ui/screens/overworld/render.ts, and src/web/render/overworldView.ts, 2026-07-26>
- Battle status effects (poison, burn, stun, slow, wet, oiled, chilled, frozen, shocked) tick at the start of the afflicted actor's turn and clear entirely when battle ends. Antidote cures poison and Thermal Salts cure burn/chilled; both are single-use, MP-free, and consumed on use even if nothing needed curing. Every Heal-kind skill (Heal, Second Wind) additionally cleanses all of the caster's own status effects on cast - the documented Heal-cleanse decision that rewards the MP spend with a full reset a cure item does not offer. <source: src/engine/combat/resolution.ts, src/engine/combat/skills.ts, and src/engine/loot/consumables.ts, 2026-07-26>
- Battle carries status effects (poison, burn, stun, slow, wet, oiled, chilled, frozen, shocked) and an elemental damage type (physical, fire, ice, lightning, poison) that applies on hit, ticks at the start of the afflicted actor's turn, and clears at battle end. `BattleScreen` shows each afflicted actor (the acting party member and enemies) a badge per active effect with turns remaining, and colors a damage log line by its element so a fire hit reads differently from ice, lightning, poison, or plain physical damage. <source: src/engine/combat/statusEffects.ts, src/engine/combat/resolution.ts, and src/ui/screens/BattleScreen.tsx, 2026-07-26>
- After a battle victory or chest open, the loot log shows rarity-colored item names for kept items and, when the auto-dismantle filter discards items, a summary line ("Dismantled N item(s) -> Gg") with the gold total. The message-log UI (both Ink terminal and Pixi web renderer) renders each loot line in the item's rarity color when present, falling back to the gold-toned "loot" kind color otherwise. <source: src/engine/state/types.ts, src/engine/combat/resolution.ts, src/engine/state/store.ts, src/ui/components/MessageLog.tsx, and src/web/render/sceneView.ts, 2026-07-27>

- The PixiJS overworld renderer's `grass`/`water` atlas crops are exhaustively-verified clean, fully-opaque single-color regions of the vendored Tiny Overworld sheet (not eyeballed), and grass tiles get sparse deterministic ground-clutter decorations (tuft/flower/pebble icons) for per-tile variety; a true cross-biome shore/corner auto-tile blend remains a documented follow-up. <source: src/ui/tiles/sources.ts, src/ui/tiles/overworldVariants.ts, and assets/README.md, 2026-07-26>
- The PixiJS renderer plays renderer-local visual effects derived from state deltas across renders, never new `GameEvent`s (the terminal renderer is unaffected): battle hits/spells spawn a hand-rolled particle burst colored by the hit's elemental log tag (`theme.element`) - a narrow melee spark arc for physical, a radial burst for fire/ice/lightning/poison - plus a brief position-shake on the struck sprite and heal sparkles on an HP rise; the dungeon scene drifts ambient dust motes/embers through the torchlight. Both share one pooled, capacity-capped emitter (`src/web/render/particles.ts`) over a real Pixi `ParticleContainer`. Every effect is additive and disabled under `prefers-reduced-motion` (ambient fields, bursts, and hit-shake all stop; damage numerals and name/HP text stay). Keyed effects are procedural today, not yet the pre-animated Minifantasy sprite sheets ART_DIRECTION.md §6 calls for - those sheets aren't vendored (see assets/README.md) - but sit behind the same `BattleDrawFactory`/`DungeonDrawFactory` seam so swapping in real frames later is a factory change, not a view rewrite. <source: src/web/render/particles.ts, src/web/render/battleView.ts, and src/web/render/dungeonView.ts, 2026-07-27>
- A Character Sheet screen (Shift+C, anywhere outside battle) shows the current party member's name, class, level, XP/XP-to-next, core stats with the equipment bonus broken out (base+bonus=total via `effectiveStats`), derived ATK/DEF/SPD, all four equipment slots, and known skills with MP costs; Left/Right switches party member and Esc returns to the scene it was opened from. It is pure display (no engine changes) and reuses `EQUIP_SLOTS` from the village Store view. Unspent skill points shows a static 0 placeholder until skill trees ship. <source: src/ui/screens/CharacterSheetScreen.tsx and src/ui/screens/character/interaction.ts, 2026-07-27>
- The overworld's 3 fixed dungeon entrances are each bound to one of the curated story dungeons (`DUNGEONS` in `src/data/dungeons.ts`), ordered so tier ascends with chebyshev distance from the village: the nearest entrance leads to the lowest-tier dungeon. `dungeonWaypointId(entranceIndex)` resolves to the story dungeon's id (falling back to a generic id if an entrance has no matching def), so entering an entrance, its waypoint, and its generated dungeon layout all key off the same id. <source: src/engine/world/overworld.ts and src/engine/world/waypoints.ts, 2026-07-27>
- Wandering-encounter enemies are split into a front and back formation row (`BattleEnemy.row`, defaulting to front): only the first `FRONT_ROW_SIZE` (2) enemies stand in front, and any overflow forms the back row; the party itself stays a flat line. A basic attack cannot target a living back-row enemy while any front-row enemy still survives - the classic Wizardry melee-reachability rule - and the command is rejected outright rather than redirected; skills always ignore this rule. <source: src/engine/combat/types.ts and src/engine/combat/resolution.ts, 2026-07-28>
- A skill's target shape (`single`, `row`, `column`, `allEnemies`, `randomN`, `self`, `ally`, `allAllies`) expands into a concrete target list through one shared resolver used by both a party member's Skill command and a monster's turn: `row` hits a whole enemy row (Hailstorm), `column` pierces one lane through both rows ignoring the melee-reachability rule (Skewer), `allEnemies` blasts every living enemy (Meteor), and `randomN` hits a fixed number of distinct random living targets (Scattershot). Every target rolls its own crit, damage, and status application independently. A monster carrying an attack-kind skill (e.g. the Dungeon Guardian's Cleave/Meteor) always casts one instead of a basic attack. <source: src/engine/combat/skills.ts and src/engine/combat/resolution.ts, 2026-07-28>
- Each story `DungeonDef` (src/data/dungeons.ts) declares `floorBands` - contiguous floor ranges each pointing at an existing tiered loot table ref - so deeper floors within a dungeon draw from higher-ilvl tables than shallow ones, using the same dungeon/seed. Victory loot (`rollVictoryLoot`) and chest loot (`rollChestLoot`) both resolve the current floor's band and feed its table into the existing `weightedPick` path instead of the monster's own tier or a floor-global table; unmapped dungeon ids fall back to the first story def until ROG-90's entrance assignment lands. <source: src/data/dungeons.ts and src/engine/loot/resolution.ts, 2026-07-28>
- Stepping onto a story dungeon entrance resolves the def via `findDungeon` and logs its name and recommended level (e.g. "You descend into Sunken Crypt (recommended level 1)") instead of a generic descend message; the UI only ever sees the resolved log text, never the `DungeonDef` shape. <source: src/engine/state/store.ts, 2026-07-27>
