# World

Overworld, village, and dungeon-entrance facts: navigation, landmarks, and
tier placement. Part of the golden product SSOT (see
`.botfile/memory/index.md`); `pnpm docs:lint` reports drift.

- The overworld/village support fast travel: evac exits any dungeon (outside battle) to the overworld on the entrance tile with dungeon progress untouched, and zoom teleports between landmarks (village, dungeon entrances) already visited this run; neither triggers an encounter or resets the overworld danger meter. <source: src/engine/world/waypoints.ts and src/engine/state/store.ts, 2026-07-25>
- The village is a multi-tile landmark: it occupies a 2x2 footprint derived from its anchor cell (`map.village`) plus a fixed size lookup, not stored per-cell. Both renderers draw it as one coherent structure - the Ink TUI with four distinct ASCII glyphs, the PixiJS renderer with one contiguous sprite tiled from per-cell texture sub-regions - and it stays enterable and non-overlapping with other terrain/landmarks from any of its four cells. <source: src/engine/world/landmarks.ts, src/ui/screens/overworld/render.ts, and src/web/render/overworldView.ts, 2026-07-26>
- The overworld places one dungeon entrance per entry in the `DUNGEONS` table (`src/data/dungeons.ts`, 4 story dungeons today - Sunken Crypt, Howling Cave, Forgotten Ruins, Drowned Temple), ordered so tier ascends with chebyshev distance from the village: the nearest entrance leads to the lowest-tier dungeon. `dungeonWaypointId(entranceIndex)` resolves to the story dungeon's id (falling back to a generic id if an entrance has no matching def), so entering an entrance, its waypoint, and its generated dungeon layout all key off the same id. Each dungeon's `DungeonState` also carries that def's theme id (`dungeonDefFor`, falling back to the first story def for an unmapped id), and both renderers key their first-person wall/depth-band color ramp off that theme id (`dungeonRamp`, `src/ui/theme.ts`) instead of the dungeon's waypoint index - so each entrance reads as a visibly distinct palette. Entering a dungeon and descending a floor emit theme-specific message-log flavor lines (`dungeonEntryFlavor`/`dungeonDescendFlavor`, `src/data/dungeons.ts`). Adding a story dungeon is one `DungeonDef` entry plus a theme palette (message-log flavor + renderer color ramp) - the overworld's entrance count derives from `DUNGEONS.length`, so a new entry gets a placed, playable entrance with zero other `src/engine` edits (proven by ROG-95's 4th dungeon and its full-loop `overworld -> enter -> descend -> boss -> clear` test, which also confirms `allStoryDungeonsCleared` - the derived all-cleared boolean ROG-28's endgame trigger consumes - only flips once every story dungeon's boss has fallen). <source: src/engine/world/overworld.ts, src/engine/world/waypoints.ts, src/data/dungeons.ts, src/engine/world/dungeon.ts, src/ui/theme.ts, and src/engine/state/store.ts, 2026-07-28>
- Stepping onto a story dungeon entrance resolves the def via `findDungeon` and logs its name and recommended level (e.g. "You descend into Sunken Crypt (recommended level 1)") instead of a generic descend message; the UI only ever sees the resolved log text, never the `DungeonDef` shape. <source: src/engine/state/store.ts, 2026-07-27>
